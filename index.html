왜 Top-Down인가?

실무에서 바로 써먹을 수 있는 능력은 Top-Down이 압도적으로 빠릅니다.

높음 낮음
시작 6개월 1년 2년
Top-Down — 앱을 만들며 필요한 것부터
Bottom-Up — 기초 이론부터 차근차근
🚀
앱을 만들 수 있는 시점
Top-Down은 첫 달부터 동작하는 앱을 만듭니다.
Bottom-Up은 자료구조를 배우는 중입니다.
🔧
문제 해결 능력
실제 버그를 잡아본 사람이 디버깅을 압니다.
교과서 예제만으로는 실전 감각이 생기지 않습니다.
💰
생존과 수익
빠르게 결과물을 내야 살아남는 시대입니다.
완벽한 준비보다 빠른 실행이 기회를 만듭니다.

하지만 대학 커리큘럼 순서가 주는 장점도 분명히 존재합니다.

높음 낮음
시작 1년 2년 4년+
Bottom-Up — 대학 커리큘럼 순서
Top-Down — 실무 중심 학습
🧱
탄탄한 기초 체력
OS, 컴퓨터구조, 알고리즘을 체계적으로 쌓으면
어떤 기술이 와도 본질을 꿰뚫을 수 있습니다.
🔬
깊은 이해
Top-Down은 "왜?"를 나중에 채우지만,
Bottom-Up은 처음부터 원리를 이해하고 넘어갑니다.
🎯
그래서 이 커리큘럼은
Top-Down으로 빠르게 시작하되,
각 단계에서 필요한 기초를 깊이 있게 다룹니다.

이런 상황에서, 어떤 걸 선택하시겠습니까?

앱을 만들다 보면 자연스럽게 마주치는 선택의 순간입니다.
자료구조를 몰라도 앱은 만들 수 있습니다. 하지만 잘못 고르면 앱이 멈춥니다.

상황 1

연락처 앱에서 이름을 검색합니다. 연락처가 10,000개일 때, 어떻게 저장하시겠습니까?

Array를 선택했다면
// 10,000개를 처음부터 하나씩 비교
for contact in contacts {
  if contact.name == "김민수" { ... }
}
검색 시간
최악 10,000번 비교

사용자가 글자를 입력할 때마다 10,000개를 전부 훑습니다.
타이핑할 때마다 버벅거리는 검색창 — 사용자는 앱을 삭제합니다.

Dictionary를 선택했다면
// key로 바로 접근 — 해시 함수 한 번
let result = contacts["김민수"]
// 끝.
검색 시간
평균 1번 (O(1))

10,000개든 100만 개든 거의 즉시 찾습니다.
이것이 해시 테이블의 힘이고, 이것을 알아야 하는 이유입니다.

상황 2

쇼핑 앱에서 "최근 본 상품"에 같은 상품이 중복되면 안 됩니다. 무엇을 사용하시겠습니까?

Array를 선택했다면
// 매번 전체를 순회해서 중복 확인
if !recentItems.contains(item) {
  recentItems.append(item)
}
중복 확인
매번 전체 순회 O(n)

상품을 볼 때마다 배열 전체를 탐색합니다. 100개면 100번, 1000개면 1000번입니다.
스크롤할 때마다 느려지는 앱이 됩니다.

Set을 선택했다면
// insert하면 중복은 자동으로 무시됨
recentItems.insert(item)
// 끝. 확인할 필요 없습니다.
중복 확인
자동 처리 O(1)

Set은 수학의 집합과 같습니다. 같은 원소가 들어갈 수 없는 구조 자체가 답입니다.
이런 선택이 앱의 성능을 결정합니다.

이것이 바로 자료구조를 배워야 하는 이유입니다.
"어떤 걸 쓰든 동작은 합니다"가 아니라, "무엇을 고르느냐가 앱의 생사를 가릅니다."
그리고 이 커리큘럼은 바로 이 순간에 필요한 지식을 가르칩니다.
